# Arsenal PRO — сервер лицензий

Тестовый режим по умолчанию. Реальный магазин не активировать до завершения интеграции, проверки чеков и оферты. Без зависимостей Python 3.11+, SQLite. Секреты только в окружении сервера, не в GitHub, APK или клиентских запросах. MerchantLogin arsenal-rybaka, SHA256, цена 399.00. /result POST проверяет сумму, подпись, номер, режим и идемпотентность; Success URL не выдаёт лицензии. Код восстановления — случайные 32 байта в base64url, хранится в БД только SHA256. /order и /status принимают JSON {code,mode}. Не добавлять код восстановления в URL и логи. Режим test и live строго разделены. Возвраты: пока ручное изменение state=refunded после подтверждённого возврата в Robokassa. Тесты: python3 -m unittest -v test_server.py.

Размещение: Linux VPS с доступным HTTPS, обратный прокси на 127.0.0.1:8765, отдельный системный пользователь, каталог /var/lib/arsenal с правами 700. Не публиковать порт Python. Указать Result URL https://ВАШ_АДРЕС/result (POST), Success URL /success (GET), Fail URL /fail (GET) только после фактического развёртывания. env ROBO_TEST_1, ROBO_TEST_2, ROBO_LIVE_1, ROBO_LIVE_2, LIVE_ENABLED=no. До включения live проверить требования Робочеков СМЗ, необходимость Receipt и реквизитов, поддержку возвратов, резервные копии SQLite, ограничение запросов прокси и требования 152-ФЗ. Не хранить email/имя покупателя в этой БД. Сайт не принимает платёжные данные.

Это код сервера, не развёрнутый сервис. Нет подтверждения наличия VPS, домена или доступа к управлению сервером.
## Акция запуска
PROMO_TEST=yes / PROMO_LIVE=yes (по умолчанию оба выключены), PROMO_LIMIT=20. Сумма берётся из сохранённого заказа, подписывается и проверяется при Result. Счёт 199 ₽ занимает место атомарно при создании; повтор по тому же коду не занимает новое. Учитываются все акционные счета, в том числе pending/refunded: это консервативный предел, чтобы никогда не выдать более 20 потенциально оплачиваемых акционных счетов. Не удалять pending ради освобождения места без подтверждённой отмены/истечения счёта у Робокассы; до внедрения подтверждённого аннулирования акция может остановиться раньше 20 фактических продаж. Не рекламировать остаток как число покупок. PHP на действующем хостинге необходимо адаптировать отдельно, этот файл не развернут. Клиент совместим с прежним /order.php: если цена не передана, проверяет OutSum и просит подтвердить её перед открытием оплаты. Для /status.php использовать price_cents, regular_cents, promo_remaining, promo_limit, promo_enabled, reserved из reference. Перед запуском проверить чеки на фактическую сумму, ограничения провайдера, живые платежи и возвраты.
